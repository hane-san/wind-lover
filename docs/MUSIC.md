# 旅の音楽

物悲しい旋律と広がる余韻に、前へ進むリズムを重ねた4曲です。既存の他ゲームから旋律・音源を取り込まず、新たに譜面と音色を作っています。

| 曲 | テイスト | BPM | ループ長 |
|---|---|---:|---:|
| 錆びた水平線 | 黄昏のシンセウェーブ | 124 | 約62秒 |
| 遠い街の残響 | リキッド・ブレイクビーツ | 172 | 約45秒 |
| 宙を渡る青 | 浮遊するポストロック | 108 | 約71秒 |
| 風にほどける車窓 | 弦と乾いた打楽器、6/8 | 132 | 約44秒 |

メニューの「旅の音楽」でオン・オフ、曲、音量を変更できます。初回はオフ。設定は `windlover.journey-music.v1.*` に保存し、次回は開始操作に合わせて再生します。「効果音」の切替とは独立しています。

## 実装

- `music/scores.mjs`：各曲の譜面と編成。
- `music/journey-music.mjs`：音色・オフライン音源生成関数と再生制御。
- `music/game-music.mjs`：本体のメニューと再生制御の接続。
- `assets/music/`：24 kHzステレオのループ。通常はOgg、取得・復号に失敗した場合はPCM WAVを使用。

ゲーム中に音符を生成せず、事前生成した音源を `AudioBufferSourceNode.loop` で再生します。描画や地形の生成に使うJavaScriptタイマーに再生タイミングを依存させません。生成時には2周目を切り出して前周の残響を含め、読み込み後は接続点の微小な差だけを前後8 msで補正します。曲全体の長さや終端を無音にする処理はありません。

切替先の読み込みが終わるまで現在の曲を維持し、その後0.9秒でクロスフェードします。読み込み中のオフ操作で再生が復活しないよう、要求番号で取り消しを確認しています。復号した音源のキャッシュは最大2曲。初回オフのままなら音源を取得せず、追加の音声コンテキストも作りません。

効果音の `AudioContext` を遅延取得し、別の音量経路に接続します。メニューの開閉やワールド変更で曲を頭から再生し直しません。ページが非表示になればフェードして停止し、戻った際は再開位置を使います。

## Claude向け再監査メモ

統合元として確認できた `main` と `claude/hoverboard-prototype` は、ともに `67f70ee204cd5651569054b86d327bae506f102c` でした。ユーザーの本体統合指示により、この版へ音楽を追加しています。別の場所にあるClaude改修版との同一性は確認できていません。今回の変更は音楽、メニューへの接続、操作部へのキーボード入力の保護です。地形・障害物・走行物理の変更は含みません。

監査では、上記3つのモジュール、音源、メニュー欄、`sfx.context` と `__wlAudio` の接続を一まとまりで確認してください。別版へ統合する場合も、既存の世界・物理を差し戻す必要はありません。

検証コマンド：

```sh
node --test tests/music-scores.test.mjs
python tests/music-browser.py --browser /usr/bin/chromium
```

ブラウザ検証はスマートフォン相当の縦画面で本体を開き、4曲の選択、Ogg失敗時のWAV、効果音との独立、同一AudioContextの利用、読み込み待ち、オフでの取り消し、再読み込み後の設定、音楽再生中の走行を調べます。出力を録音し、メインスレッドの1.6秒停止とクロスフェードを含む区間に100 ms以上の無音がないことを確認します。結果・録音・画面は標準で `/tmp/wind-lover-music-qa/` に保存されます。

iPhone/Safari実機でのバックグラウンド復帰、Bluetoothや通話後の音声復帰、端末負荷による音切れは、実機での確認が残っています。
