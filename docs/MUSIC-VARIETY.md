# 静けさと勇ましさが移り変わる音楽（2026-10-26）

既存の静かな12曲を残し、ゲーム内のオリジナル譜面から新しい疾走向け編成を4曲追加します。保存済みの曲ID・手動選曲・音量・オンオフは維持します。

| 追加曲 | 編成 |
|---|---|
| 砂丘を越える騎兵 | 104 BPM、乾いた太鼓と駆ける撥弦 |
| 廃線の先へ | 116 BPM、郷愁を帯びたシンセウェーブ |
| 天山に響く角笛 | 112 BPM、角笛と弦、峠を越える三拍子 |
| 星を追う航跡 | 148 BPM、浮遊する旋律と軽いブレイクビーツ |

新編成の基になるのは、このゲームの `scores.mjs` にある既存の自作譜面です。他作品の曲の転用ではありません。旋律を前へ出し、打楽器と低音を控えめに調整しています。角笛は丸い三角波と少量の鋸歯状波を混ぜ、音の立ち上がりとフィルターで耳に刺さる成分を抑えます。新編成の全体にも2.9kHzのローパスを置き、シンセや打楽器の鋭い瞬間を丸めます。

## おまかせ再生

各地域の候補を、静かな4曲＋疾走向け2曲に拡張します。出発一曲目は静かな曲から始めます。直近3曲を避け、勇ましい曲の直後は静かな曲へ、静かな曲が2曲続いたら勇ましい曲へ移ります。地域内で走り続けても変化します。手動選曲では自動変更しません。メニューでは全16曲とおまかせを選べ、疾走向けの曲には「疾走」の印を付けています。

曲の切り替えは従来どおり一曲を十分に聴いてから、戦闘の切れ目に2.4秒でクロスフェードします。戦闘開始ごとに曲を再起動する仕組みは追加しません。

## 音切れを防ぐ仕組み

- 追加音源も24kHzステレオOggへ事前に書き出します。再生中に音符をJavaScriptタイマーで発音しません。
- 前周の残響を含むループを作り、復号後の継ぎ目を前後8msで補正します。
- 元の曲は次の音源の準備が終わるまで鳴り続けます。読み込み中のオフ操作や非表示への移動は要求番号で取り消します。
- 復号キャッシュは最大2曲、共有AudioContextと独立したBGM音量経路を維持します。全16曲を一度に読み込みません。
- 新編成も実効音量 .075 以下、ピーク .65 以下へ正規化します。音源形式に対応しないブラウザでは同じ譜面をOfflineAudioContextで一度描画する従来の代替経路を使います。密度の高い新編成の代替描画には時間がかかる場合があります。

音源の保存先 `assets/music/quiet/` と読み込み関数名は互換性のため維持します。そこには静かな12曲と追加の4曲が含まれます。

## 検証

- `node --test tests/*.test.mjs`：全曲の有効性、地域候補、勇ましい曲の連続回避、静けさとの交代、手動モードと停止条件。
- `python tools/render-quiet-music.py --browser /usr/bin/chromium --ids dune-riders railbound-heart tian-shan-charge skyward-current`：実際のWebAudioから追加4曲を書き出し。
- `python tests/quiet-music-browser.py --browser /usr/bin/chromium --recordings`：全16曲の復号、長さ、音量、ピーク、継ぎ目、無音区間。事前音源だけで成功し、代替描画へ落ちないことも検査。
- `python tests/music-browser.py --three /path/to/three.min.js`：実ゲームの出力録音。追加4曲・静かな曲・おまかせ切り替えを通し、ループ、1.6秒のメインスレッド停止、メニュー、設定保存、準備中の取り消し、共有音声経路を確認します。従来曲では形式失敗時の代替描画も確認します。

ソフトウェアブラウザでの検証であり、実機の聴感・Bluetoothや通話後の復帰・すべての端末での無音切れを保証するものではありません。

### 今回の検証結果

全14ファイルのNode検証と、全16曲の実音源検査を通過しました。復号後の最大ピークは .41494、最大隣接サンプル差は .04970、最小500ms実効音量は .01353 で、形式失敗による代替描画は発生していません。ゲーム側では追加4曲と静かな曲、おまかせ切り替えを含む58.08秒を録音し、最小100ms実効音量 .01161、最大隣接サンプル差 .05091 を確認しました。1.6秒の描画停止、メニューで曲を再起動しないこと、読み込み中のオフ、設定保存、BGM再生中の走行も通過し、ページエラーはありませんでした。
