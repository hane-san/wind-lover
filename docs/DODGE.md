# 疾走と回避の改修

最新の敵・実弾・ミサイルと戦闘の緩急は [DEFENCE-RHYTHM.md](DEFENCE-RHYTHM.md) を参照してください。このページは20日の改修記録です。最新の3つの旅路、半径0.32 mの判定、9種類の弾幕は [FEATURED-JOURNEYS.md](FEATURED-JOURNEYS.md) を参照してください。

`e4df6c8` の音楽統合版を起点に、既存の世界と車両の手ざわりを保って追加した改修です。

## 回避の感覚

- 敵弾に対する自機判定を半径約2.4 mから0.65 mへ縮小。中心は `P.pos` の0.45 m上です。弾も自機も動く相対線分を調べ、フレーム間ですれ違った直接命中を取りこぼしません。
- 4.5 m以内をかすめた弾は一度だけグレイズとして数え、フローとゲージを加算します。従来、同じ近接弾で何度も速度を95%にしていた処理は除去しました。音と火花の頻度は制限し、弾数が増えても過剰にならないようにしています。
- 建物などの衝突余白も0.6 mから0.35 mへ縮小。構造物の形状やルートへの障害物追加はありません。
- 正面の6種類の弾幕は1回36〜82発。平均間隔は約0.95秒です。カーテンには車道内の抜け道を残し、二重カーテンの隙間も同じ通路を共有します。
- 弾は発射時の位置と速度で飛び、遅れて発射する列も追尾しません。路面の先の高さは発射時に予測します。屋根の下や襲撃オフでは予約済みの列も発射しません。正面の襲撃は同時に1編隊までです。

## カクつきへの対策

改修前の同一コンテナでのCPU計測では、チャンク一式の生成に最大約74 ms、遠景一式に約55 msかかる場面がありました。

地形の高さ・着色は行ごと、草木や建物は配置単位で処理を中断できるジェネレーターにしました。走行中は1フレーム約3 msを目安に進めます。再開のたびにチャンク専用のパレットと生成先を戻すため、途中で別の建造物を生成しても色・配置が混ざりません。形と当たり判定は完成後に同時に公開します。遠景も行ごとに生成し、完成するまで前の遠景を表示します。ワールド変更時は中断中の仕事を取り消します。

建材や葉を配置するたびにジオメトリを複製していた処理を、元頂点の再利用と直接の座標変換へ変更しました。描画負荷が継続した際には解像度を段階的に下げ、余裕が続けば戻します。弾数、物理、当たり判定は解像度によって変えません。

敵弾は固定長バッファと1回のPoints描画を維持しています。地面との接触による表示整理は約0.14秒おきに分散し、プレイヤーとの精密な衝突判定は毎フレーム行います。弾の色の転送は発射があったフレームだけです。

3 msは協調的な予算であり、厳密な上限ではありません。一つの建築処理、GPUへの転送、ガベージコレクションは予算を超える場合があります。開始・ワールド変更での初期生成は同期処理です。実機のフレームレートは未測定です。

## 検証と再監査

```sh
python tests/dodge-browser.py --browser /usr/bin/chromium
python tests/world-smoke.py --browser /usr/bin/chromium
python tests/music-browser.py --browser /usr/bin/chromium
```

各コマンドは `--three /absolute/path/three.min.js` でローカルのThree.js r128を使用できます。

新しい回避試験は、本体のコードを実際に動かして以下を検証します。

- 速い弾による直接命中、自機が横切る場合の命中、高速グレイズ、無敵時間、屋根の保護。
- 直進では被弾する弾を短い操舵で避けられること。試験では3秒後の横方向の差が約11.6 mとなり、回避側は装甲3を維持しました。
- 6種類の発射数と車道内の隙間。予約した弾の発射中止。
- 分割生成と一括生成で近傍の形・コライダーが一致し、取り消した生成が後から混ざらないこと。
- 生きた弾800発のCPU処理と解像度の低下・回復。

結果と画面は `/tmp/wind-dodge-qa/` に出力します。CPU計測ではソフトウェアGPUの描画を除外するため、結果は端末のFPSを表しません。実行ごとの揺れがあり、代表試験では800発の処理中央値が約0.3 msでした。

既存のルート試験で120 kmの地形、高架の迂回、駅の屋根、実走行、ストリーミング、ワールド切替を確認し、音楽の独立切替・設定保存・描画停止中の再生も確認しています。

Claudeでの再監査では `chunkSteps` / `advanceChunk` / `cancelStreaming` の状態復元と取り消し、`farSteps` の更新、`updateBullets` の相対移動判定、`assaultVolley` の抜け道を重点的に確認できます。スマートフォン実機での発熱時の負荷・弾の見やすさ・タッチ操作による連続回避は引き続き確認対象です。
